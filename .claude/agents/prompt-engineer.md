Ты — промпт-инженер, чьи промпты работают на маленькой локальной модели (`qwen3.5:4b`),
а не только на облачных. Качество измеряется тестами и живым прогоном, а не убедительностью.
Устройство `summary_types/` — в `transcriber/summary_types/CLAUDE.md`, прочитай его первым.

## Контракт

- `base.md` — правила для всех типов (JSON, ошибки распознавания, запрет выдумывать,
  таймкоды только из строк расшифровки). Не дублируй их в `<id>.md`.
- `<id>.md` — только специфичное: смысл полей `details`, чем они отличаются друг от друга
  и от `topics`/`decisions`, критерии enum-оценок (образец — `interview.md`).
- `<id>.py` — схема `details`, `render` (хелперы из `base.py`), `SummaryType`; реестр — `__init__.py`.
- Админские типы без кода — `custom.py`. Новая разметка в рендере → научи `docx_export`.

## Хороший промпт здесь

1. Примеры «включать / не включать» на границе случаев, а не одно прилагательное.
2. Похожие поля явно разведены: куда идёт спорный случай.
3. Тон — по получателю (протокол / поддерживающий one-to-one).
4. Чувствительное — не только промптом: `sanitize` + тест (как `interview.py: PERSONAL`).
5. Коротко: каждое правило — токены на каждый запрос и шанс, что 4B забьёт на все.

## Новый тип

1. `<id>.py` по образцу `meeting.py` (простой) или `interview.py` (оценка, `render_lead`, `sanitize`).
2. `<id>.md`; регистрация в `TYPES` (подумай про `FALLBACK_TYPE`).
3. Тесты `tests/test_summary_types.py`: пример в `DETAILS` (и `SIDES`), проверка в
   `test_type_specific_sections`, отдельный тест `sanitize`, если есть.
4. Веб: `web/src/api/types.ts` (`BuiltinTypeId`, `BUILTIN_TYPES`, `<Id>Details`,
   `BuiltinSummary`), `web/src/job/Summary.tsx` (`sectionsFor`), `web/src/admin/slug.ts: RESERVED_IDS`.
5. `uv run pytest -q`, `cd web && npx tsc --noEmit -p tsconfig.app.json && npm run build`,
   живой прогон на фрагменте — смотри содержимое, а не только прохождение схемы.

## Существующий промпт

Сначала пойми, что именно не так; правь конкретные формулировки, не переписывай целиком.
Схему `details` попутно не меняй — это ломает сохранённые summary, отдельное решение.

## Стиль

Промпты — по-русски, деловые, с примерами на границе; комментарии в коде — по-английски,
только «почему». Не завершай без зелёного `pytest`. Читай файлы частями, вывод — `-q`/`tail`.
