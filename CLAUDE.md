# CLAUDE.md

Транскрибация аудио (faster-whisper, модель уже с пунктуацией) → структурированное summary
(DeepSeek или локальная модель в Ollama). Устройство, команды и переменные окружения — в README.

Детали частей проекта — в их собственных CLAUDE.md (подгружаются при работе с их файлами):
`transcriber/summary_types/`, `transcriber/server/`, `web/`. Docker — в `.claude/agents/devops.md`,
прочитай перед изменением `Dockerfile`/`docker-compose.yml`.

## Команды

`make` — список коротких команд (добавляешь команду — добавь и цель). Главное:

```bash
uv run pytest                                  # тесты: без сети, моделей и Postgres (SQLite), ~7 с
uv run transcribe <audio> --no-summary         # пайплайн без LLM
docker compose up -d db                        # Postgres для веб-интерфейса (Docker — OrbStack)
uv run transcriber-web --no-browser            # API на :8000
uv run alembic revision --autogenerate -m "…"  # миграция после изменения server/db.py
cd web && npm run dev | build | lint           # интерфейс (npm, lock — web/package-lock.json)
```

Полный прогон 35-минутной записи — пара минут на CPU и ~2 ГБ модели. Для проверки нарезай
фрагмент: `ffmpeg -ss 60 -t 30 -i recordings/record.mp3 /tmp/clip.mp3`.

## Соглашения

- Пользовательский текст (CLI, сообщения, README, промпты, коммиты) — на русском;
  комментарии и docstrings в коде — на английском.
- Код — пакет `transcriber/`, команды — в `[project.scripts]` (`pyproject.toml`). Импорты
  внутри пакета относительные; `summary` в `cli.py` импортируется лениво (тянет openai).
- Ресурсы ищутся от `__file__`, а не от текущей директории: модели — в `models/` в корне
  проекта, промпты — рядом с модулями в `transcriber/summary_types/`.
- Формат расшифровки `[ЧЧ:ММ:СС] текст` — контракт между `cli.fmt_time`,
  `summary_types.transcript_duration` и промптами. Меняешь в одном месте — меняй везде.
- Схема summary связывает четыре места: `summary_types/<id>.py` (схема и рендер),
  `docx_export.py`, тесты и `web/` (`api/types.ts`, `job/Summary.tsx`). Меняешь одно — обнови все.
- Настройки моделей и типы summary в `summary.py` передаются явно: `LLMConfig` и `Registry`
  (CLI — из `.env` и встроенных типов, сервер — из базы на каждую задачу: база → `.env` →
  умолчание). Каждый запрос к модели отдаёт `Usage` через `on_usage` — так считается расход.

## Неочевидное (не «исправлять»)

- **`trust_env=False` в httpx-клиенте Ollama**: системный прокси macOS (VPN, `127.0.0.1:1082`)
  перехватывает даже localhost → 503. SSH к GitHub тоже не проходит — вероятно, из-за VPN.
- **faster-whisper на Mac — только CPU** (ctranslate2 не умеет Metal). `compute_type="int8"`
  (`cli.COMPUTE_TYPE`) заметно быстрее float32 почти без потери качества — не менять.
- **`vad_filter=True`** в `cli.transcribe()`: без Silero VAD модель «галлюцинирует» фразы на тишине.
- **Язык** — `WHISPER_LANGUAGE` (по умолчанию `ru`), `auto` → `language=None` (автоопределение
  faster-whisper); флаг `--language` важнее `.env`.
- **DeepSeek** по умолчанию рассуждает, рассуждения тратят `max_tokens` (~3k на 35 минут) —
  поэтому лимит 32k. Актуальные имена моделей проверяй в документации DeepSeek.
- **Ollama по умолчанию режет контекст до 4096 токенов** без ошибки — `num_ctx` задаётся явно
  по размеру запроса, запросы идут в нативный `/api/chat`, не в OpenAI-совместимый.
- **Качество `qwen3.5:4b`**: JSON по схеме стабилен, но путает стороны встречи и выдумывает
  детали; пожелания пользователя к версии выполняет примерно через раз. DeepSeek точнее.
  Режим `auto` выбирает провайдера только по размеру контекста, не по качеству.
- **Журнал моделей** (`transcriber/log.py`, `LOG_LEVEL`): только метаданные — размеры, время,
  токены, типы ошибок, пути полей из `e.errors()`. Никогда текст расшифровки, промптов, ответов,
  summary, пожеланий пользователя, ключей и `str(e)` у ValidationError/ошибок API — есть тест
  с маркером. В CLI выключен (пользователю говорят `print` по-русски), в сервере — INFO.
- **Админ не видит содержимое чужих записей** — только метаданные и расход. Это решение о
  приватности (собеседования, one-to-one): не добавлять без явной просьбы пользователя.

## Работа с репозиторием

- Не читать и не выводить `.env`.
- `models/` и `recordings/` (записи, расшифровки и summary пользователя) не трогать и не коммитить.
- База веб-интерфейса (Postgres в Docker, volume `pgdata`) — тоже данные пользователя: для
  экспериментов создавай отдельную базу (`CREATE DATABASE …` + `DATABASE_URL`) и удаляй её после.
- Коммиты — только по просьбе пользователя. `git push` не делать — пользователь отправляет сам.
- Агент `.claude/agents/project-architect.md` — аудит структуры; по умолчанию только отчёт.
