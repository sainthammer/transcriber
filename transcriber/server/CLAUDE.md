# Сервер веб-интерфейса

- Тяжёлая работа — в `Pipeline` (в тестах подменяется `FakePipeline`). Две очереди в `jobs.py`,
  у каждой свой фоновый поток: расшифровка (CPU) и summary (сеть) — перегенерация summary не ждёт
  чужую длинную запись. После расшифровки задача снова `queued`, уже в очереди summary. Живое состояние — в памяти `JobManager`, в Postgres (`jobs`) пишется на
  смене стадий, файлы — в `recordings/jobs/<id>/`.
- Ошибка summary не делает задачу ошибочной (`summary_error`): расшифровка остаётся результатом,
  а при перегенерации — и прежний summary.
- Версии summary — таблица `summary_versions` (последние 20 на запись), текущая —
  `jobs.summary_version_id`; возврат к версии перезаписывает `summary.md`/`summary.json`.
  О смене текущей версии открытые вкладки узнают из `summary_changed` в `/api/events`.
- Каждый маршрут `/api/*`, кроме входа, требует сессию (`Depends(current_user)`), записи
  фильтруются по `user_id`: чужая запись — 404, не 403. Админские — в `admin.py` под `admin_user`.
- Схема базы — `db.py`; меняешь модели — делай миграцию Alembic. Тесты используют SQLite
  (`create_all`), поэтому никаких Postgres-only конструкций в запросах и миграциях.
- SSE-потоки сами не заканчиваются: по Ctrl+C `main()` в `app.py` ставит `app.state.stopping`,
  и циклы потоков выходят. Без этого uvicorn ждёт открытые вкладки вечно.
- Журнал: `[job <id>]` берётся из contextvar воркера; уровень uvicorn (`warning`) — отдельно.
- **API-ключи в базе зашифрованы** (`security.SecretBox`, Fernet от `SECRET_KEY`). Без
  `SECRET_KEY` ключ генерируется в `instance/secret_key`; при смене ключа сохранённые значения
  не расшифровываются и молча уступают `.env` — это ожидаемо.
- **Первый вход**: админ из `ADMIN_EMAIL`/`ADMIN_PASSWORD` при пустой таблице `users` или
  `transcriber-admin create-user --admin`. Старые `recordings/jobs/*/job.json` импортируются
  первому админу при каждом старте (импортированные пропускаются, файлы не удаляются).
